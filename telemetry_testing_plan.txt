End-to-End Testing Plan – Telemetry Platform

Objective Validate the full telemetry system including: - Ingestionz
API - Kafka event flow - MongoDB durability - Redis real-time metrics -
Metrics API (admin-protected read layer)

------------------------------------------------------------------------

PHASE A – Ingestion API Tests

A1 – Valid Event POST /track Header: X-Client-Role: service Expected: -
HTTP 202 - Kafka producer logs success

A2 – Missing Role Header Expected: - HTTP 401

A3 – Invalid Role Expected: - HTTP 403

A4 – Invalid Payload Expected: - HTTP 422

------------------------------------------------------------------------

PHASE B – Kafka → MongoDB Tests

B1 – Event Stored - Send event - Verify in MongoDB

B2 – Idempotency - Restart MongoDB consumer - Ensure no duplicate
event_id

B3 – Kafka Downtime Simulation - Stop Kafka - Send /track Expected: -
API still returns 202 - Error logged

------------------------------------------------------------------------

PHASE C – Kafka → Redis Tests

C1 – Counter Increment - Send multiple events - Verify events:count:

C2 – Active Users - Verify active_users set

C3 – TTL Behavior - Check TTL - Wait for expiry - Verify key removed

C4 – Last Seen - Verify user:last_seen:

------------------------------------------------------------------------

PHASE D – Metrics API Tests (Admin Only)

D1 – GET /metrics/events D2 – GET /metrics/events/{event_type} D3 – GET
/metrics/active-users D4 – GET /metrics/user/{user_id}

Validate: - Correct JSON - Missing keys handled - No raw Redis keys
exposed

D5 – Non-admin → 403 D6 – Missing header → 401

------------------------------------------------------------------------

PHASE E – Full Pipeline Simulation

E1 – Multi-user events - Verify MongoDB + Redis consistency

E2 – Restart consumers - MongoDB no duplicates - Redis continues
updating

------------------------------------------------------------------------

PHASE F – Performance Metrics

Measure: - API latency - Events/sec - MongoDB write latency - Redis
response time - Stability under burst load

------------------------------------------------------------------------

Success Criteria: - No crashes - No data inconsistency - Read and write
paths properly separated
